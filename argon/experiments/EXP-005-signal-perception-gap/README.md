## 1. Synthetic Self-Test (`calibration.report.json`)

`dotnet run --project argon/src/Argon.Engine -- exp005` regenerates nine synthetic stimuli with fixed seeds (60 fps 32×32 mouth-region frames and 16 kHz mono audio) under `stimuli/` and runs the detector on them. The stimuli are not versioned; their SHA-256 hashes are recorded in [`data/raw/CORPUS_MANIFEST.json`](../../../data/raw/CORPUS_MANIFEST.json) and are reproduced exactly on each run.

> **What this test can and cannot show.** The stimuli are generated by code written together with the detector. Playback tracks reuse the master's onset times exactly and the live track receives injected timing jitter, so the live/playback separation below is true **by construction**, and the timing error reflects idealized signals. The test shows that the code runs and that its timing conventions are unbiased. It says nothing about accuracy on real faces, lighting, or camera angles, and it tests no hypothesis about perception.

**Correction from v0.1 (November 9, 2026).** The first version reported a bias of −5.21 ms (MAE 5.21 ms) and attributed it to frame sampling. The cause was a timing convention: the acoustic flux was stamped 2.5 ms late and the visual frame difference half a frame (8.3 ms) late. Stamping both at the midpoint of the interval they span removed the constant bias. See `MeasureStimulusFromDisk` in the detector.

$\sigma_{\text{LA}}$ (lip-to-audio onset dispersion, used without the studio master for $H_{2b}$) does not separate the synthetic live and playback stimuli, because the generator gives both the same visual jitter. Its threshold is set only on pilot recordings.

## 2. Verification of the Lag-Generation Commands

The re-encoded `adelay` / `atrim` commands in protocol Section 4.3 were checked by converting a synthetic stimulus to MP4, generating all eight variants, and measuring them through the real-video path (`exp005-video`). Recovered lags were within 1 ms of the intended offsets. The stream-copy `-itsoffset` commands from protocol 0.1 produced −65 ms for an intended −60 ms in the same test.

## 3. Commands for the Principal Investigator

```powershell
# Software self-test (regenerates synthetic stimuli and calibration.report.json)
dotnet run --project argon/src/Argon.Engine -- exp005

# Measure one real recording against its studio master. Arguments: video, master, true lag (ms), is-playback, mouth crop (w:h:x:y in pixels).
# Each run saves measurements/<file name>.json, which exp005-analyze uses.
dotnet run --project argon/src/Argon.Engine -- exp005-video video/exp005/stim_live_A_pos060ms.mp4 video/exp005/master_A.wav 60 false "crop=220:160:850:520"
dotnet run --project argon/src/Argon.Engine -- exp005-video video/exp005/playback_A.mp4 video/exp005/master_A.wav 0 true "crop=220:160:850:520"

# Gap metrics after observer files are in responses/. Optional: responses directory and the sigma_LA threshold (ms) fixed in the pilot.
dotnet run --project argon/src/Argon.Engine -- exp005-analyze
dotnet run --project argon/src/Argon.Engine -- exp005-analyze argon/experiments/EXP-005-signal-perception-gap/responses 6.0
```

`exp005-analyze` uses real-video measurements from `measurements/` when present. Without them it falls back to the synthetic self-test and prints a warning; that output is not valid for hypothesis tests. The current $W_{\text{human}}$ estimate interpolates linearly between tested offsets; the protocol requires a logistic fit before main-study analysis.
